# Автоматизированный пайплайн сборки сферических панорам БПЛА и адаптивной замены неба

> **Назначение документа:** Данный `README.md` является полным техническим заданием и архитектурной спецификацией для ИИ-агента / разработчика. На его основе необходимо реализовать модульный производственный пайплайн на языке Python, упакованный в Docker-контейнер.

---

## 1. Контекст и постановка задачи

Операторы БПЛА (основные модели — **DJI Matrice 4E (M4E)** и **DJI Matrice 3E (M3E)**, возможны и другие модели) снимают серию перекрывающихся кадров (обычно от $25$ до $33+$ снимков) для формирования полной сферической (эквиректангулярной) панорамы разрешением $15000 \times 7500$ пикселей ($360^\circ \times 180^\circ$). Нижняя полусфера (надир) в сериях заполнена, однако верхняя часть неба (зенит) отсутствует, так как подвес дрона снимает только под небольшим углом выше горизонта.

Съемка ведется преимущественно в **городском и строительном ландшафте** на малой относительной высоте ($\approx 30\text{--}40\text{ м}$). В кадр часто попадают высотные здания, башенные краны и опоры/провода ЛЭП в непосредственной близости от дрона, выступающие выше линии математического горизонта ($Y < 3750$).

Пайплайн состоит из двух последовательных модулей:

1. **Модуль 1: Детерминированная сборка панорамы без геометрических разрывов (Stitching).**
   Из-за малой высоты съемки и ветрового смещения дрона между кадрами возникает параллакс на зданиях, кранах и дорогах, а облака смещаются по ветру. Слепые сшиватели (вроде Autopano Giga) дают ошибки геометрии («ступеньки» на дорогах, разрезанные конструкции). Сборка должна опираться на точные углы подвеса из XMP-метаданных, отсекать контрольные точки на облаках и объектах с сильным параллаксом, а швы прокладывать методом разреза графов (`multiblend`).
2. **Модуль 2: Автоподбор, выравнивание по солнцу и градиентная вставка неба с защитой высотных объектов (Sky Replacement).**
   Скрипт должен автоматически выбрать наиболее подходящий по погоде, высоте солнца, цвету и фактуре облаков шаблон неба ($15000 \times 3750$ пикселей) из базы заготовок, совместить его по азимуту солнца с панорамой, выполнить мягкую цветокоррекцию и смешать с исходной панорамой через сглаженную градиентную маску, сохранив при этом четкие контуры зданий, кранов и проводов ЛЭП, выступающих выше горизонта.

## 2. Спецификация входных и выходных данных

### 2.1. Исходные снимки с дрона
Серия файлов формата JPEG (`PANO_0001.JPG` ... `PANO_00XX.JPG`, количество кадров варьируется от $25$ до $35+$), содержащих стандартные блоки `EXIF` (включая `GPSInfo` и вложенный каталог `ExifIFD` `0x8769`) и пакет `XMP` (`<x:xmpmeta>`).

**Ключевые метаданные:**
* **EXIF / GPS:**
  * `Make`: `DJI`, `Model`: `M4E` / `M3E` (и др.)
  * `DateTime`: `2026:10:17 11:21:14` (**Важно:** время всегда **местное** для точки съемки!)
  * `GPSLatitude`, `GPSLatitudeRef`, `GPSLongitude`, `GPSLongitudeRef`, `GPSAltitude`
  * Каталог `ExifIFD` (`0x8769`): `ExposureTime`, `FNumber`, `ISOSpeedRatings`, `FocalLength`, `FocalLengthIn35mmFilm`.
* **XMP (`drone-dji:*`):**
  * `drone-dji:AltitudeType`: `RtkAlt` (или барометрическая при отсутствии RTK)
  * `drone-dji:AbsoluteAltitude`: `+890.621`, `drone-dji:RelativeAltitude`: `+32.953`
  * `drone-dji:GimbalRollDegree`: `+0.00`
  * `drone-dji:GimbalYawDegree`: `+0.20` ($0^\circ$ — Север, $+90^\circ$ — Восток, $-90^\circ$ — Запад, $\pm 180^\circ$ — Юг)
  * `drone-dji:GimbalPitchDegree`: `-17.50` ($0^\circ$ — горизонт, $-90^\circ$ — надир строго вниз)
  * `drone-dji:FlightRollDegree`, `FlightYawDegree`, `FlightPitchDegree`
  * Опционально: `DewarpData`, `CalibratedFocalLength`.

### 2.2. База заготовок неба (Sky Templates)
* **Разрешение:** $15000 \times 3750$ пикселей (верхняя половина эквиректангулярной сферы от зенита $Y = 0$ до горизонта $Y = 3750$).
* **Бесшовность:** Замкнутая $360^\circ$-панорама по горизонтали (край $X = 0$ бесшовно стыкуется с $X = 14999$).
* **Положение солнца:** По горизонтали солнце во всех заготовках **всегда зафиксировано строго по центру** ($X_{\text{sky}} = 7500$). Высота солнца $Y_{\text{sky}} \in [0, 3750]$ неизвестна заранее и должна определяться автоматически скриптом индексации (с возможностью ручного переопределения в `sky_catalog.json`).

### 2.3. Выходной файл панорамы
* **Формат и разрешение:** JPEG ($15000 \times 7500$), максимальное качество (`quality=96..98`, субдискретизация хромы `4:4:4` / `subsampling=0` для сохранения четкости проводов ЛЭП и мелких деталей).
* **Метаданные выходного файла:**
  1. Полный перенос геолокации (`GPSInfo`), даты съемки (`DateTimeOriginal`) и модели камеры из первого (опорного) снимка серии.
  2. Вшивание XMP-тегов стандарта **Google Photo Sphere (`GPano`)**, аналогично Autopano Giga, для корректного открытия во всех $360^\circ$-вьюверах:
     * `GPano:UsePanoramaViewer = True`
     * `GPano:ProjectionType = equirectangular`
     * `GPano:FullPanoWidthPixels = 15000`, `GPano:FullPanoHeightPixels = 7500`
     * `GPano:CroppedAreaImageWidthPixels = 15000`, `GPano:CroppedAreaImageHeightPixels = 7500`
     * `GPano:CroppedAreaLeftPixels = 0`, `GPano:CroppedAreaTopPixels = 0`
     * `GPano:PoseHeadingDegrees = 0.0` (так как центр панорамы $X = 7500$ ориентирован строго на Север).

## 3. Архитектура Модуля 1: Сборка панорамы (Python + Hugin CLI + Multiblend)

Пайплайн не должен зависеть от конкретного числа кадров ($25$, $26$, $33$ и т.д.) или модели дрона. Все параметры инициализируются динамически из метаданных.

### Шаг 1.0. Предварительная фильтрация входных файлов и режим готовой панорамы (`SKY_ONLY`)
Во входных папках вместе с сырыми кадрами часто присутствуют уже собранные панорамы (`0.jpg`, `0_full.jpg`, `full.jpg` $15000 \times 7500$, а также внутрикамерные сшивки дрона `DJI_*_V.JPG` $14400 \times 7200$), которые содержат скопированные XMP-теги `drone-dji:*` опорного кадра. Перед сборкой выполняется трехступенчатая очистка (`filter_series_frames`):
1. **Отсечение готовых панорам:** исключаются файлы с XMP-тегами свойств `GPano:*` (`ProjectionType`, `UsePanoramaViewer`, `FullPanoWidthPixels`), сферическим соотношением сторон `2:1` ($\left|W/H - 2.0\right| < 0.08$), шириной $W \ge 10000\text{ px}$ или суффиксом `_full` / `full`.
2. **Проверка телеметрии и разрешения сенсора:** отбрасываются случайные изображения без тегов `drone-dji:GimbalYawDegree` / `GimbalPitchDegree` и файлы, чье разрешение $(W, H)$ отличается от основного разрешения серии.
3. **Удаление дубликатов:** отбрасываются побайтовые копии (SHA-256) и угловые дубликаты на сфере ($\Delta\theta < 3.0^\circ$ между 3D-векторами оптической оси подвеса с учетом вырождения курса `Yaw` в надире $\text{pitch} \approx -90^\circ$).
4. **Автоматический режим `SKY_ONLY` (только Модуль 2):** если после фильтрации в папке нет сырых кадров ($\text{raw} = 0$), но присутствует уже сшитая панорама без неба (`1.jpg` $15000 \times 7500$ или внутрикамерная сшивка `DJI_*_V.JPG` / `*_Pano_*.JPG` $14400 \times 7200$), **Модуль 1 пропускается**: заготовка приводится к размеру $15000 \times 7500$, для неё строится маска покрытия `alpha_mask`, и сразу запускается **Модуль 2 (автоподбор и градиентная вставка неба)**.

### Шаг 1.1. Динамический расчет HFOV и генерация `initial.pto`
1. Скрипт читает все JPEG-файлы из входной директории, извлекает $(W, H)$, `ExifIFD` и XMP-теги `drone-dji:*`.
2. **Динамический расчет горизонтального угла обзора ($\text{HFOV}$):**
   По тегу `FocalLengthIn35mmFilm` ($f_{35}$, обычно $24\text{ мм}$ у M3E/M4E) и соотношению сторон кадра ($4:3$, диагональ $35\text{ мм}$ кадра равна $\sqrt{36^2 + 24^2} = 43.266\text{ мм}$, а для пропорции $4:3$ эффективная ширина сенсора $w_{35} \approx 34.56\text{ мм}$) вычисляется начальный угол обзора:
   $$\text{HFOV} = 2 \cdot \arctan\left(\frac{36.0}{2 \cdot f_{35}}\right) \cdot \frac{180^\circ}{\pi} \quad (\text{при отсутствии } f_{35} \text{ берется дефолт } 73.7^\circ)$$
3. Формируется файл `initial.pto`:
   * Выходной холст: эквиректангулярная проекция (`f2`), `w15000 h7500 v360`.
   * Каждому снимку прописываются `y` (`GimbalYawDegree`), `p` (`GimbalPitchDegree`), `r` (`GimbalRollDegree`).
   * В центре панорамы ($X = 7500$) жестко фиксируется направление на Север ($\text{Yaw} = 0^\circ$).

### Шаг 1.2. Поиск контрольных точек только между соседями (`cpfind`)
```bash
cpfind --prealigned --fullscale -o cp_raw.pto initial.pto
```
Флаг `--prealigned` ищет точки только между геометрически перекрывающимися кадрами согласно углам подвеса, корректно обрабатывая как сетку из $25$, так и из $33+$ кадров.

### Шаг 1.3. Очистка точек на небе и фильтрация параллакса на постройках/ЛЭП
1. **Удаление точек неба в Python:** Для всех кадров верхнего ряда (`GimbalPitchDegree` $> -25^\circ$) скрипт рассчитывает положение линии горизонта в пикселях кадра и удаляет из `.pto` все контрольные точки (`c ...`), лежащие выше линии горизонта (чтобы плывущие облака не искажали геометрию).
2. **Отсечение параллакса высотных объектов (`cpclean`):**
   В городском и строительном ландшафте часть точек попадает на близкие опоры ЛЭП, краны и крыши. Запуск:
   ```bash
   cpclean -n 1.5 -o cp_clean.pto cp_no_sky.pto
   ```
   отбрасывает точки, не вписывающиеся в основную сферическую модель земли.

### Шаг 1.4. Управляемая оптимизация и предохранитель (Sanity Check)
1. Оптимизация геометрии с удержанием горизонта и курса по первому (опорному) кадру:
   ```bash
   pto_var --opt="y,p,r,v,b,d,e,!y0,!p0,!r0" -o opt_vars.pto cp_clean.pto
   autooptimiser -n -o opt_geom.pto opt_vars.pto
   ```
2. **Sanity Check (Python):** Скрипт сверяет оптимизированные углы $(y, p, r)$ каждого снимка с исходными `GimbalYawDegree / Pitch / Roll`. Если любой кадр отклонился сильнее чем на $3.5^\circ$ (например, из-за обилия проводов или однородной крыши), его углы принудительно возвращаются к значениям подвеса RTK с учетом медианной поправки соседних кадров.

### Шаг 1.5. Фотометрическая коррекция и сшивка с сохранением альфа-канала
1. Выравнивание экспозиции и виньетирования:
   ```bash
   pto_var --opt="Eev,Vb,Vc,Vd,!Eev0" -o photo_vars.pto opt_geom.pto
   vig_optimize -o final.pto photo_vars.pto
   ```
2. Репроекция и сшивка:
   ```bash
   nona -g -m TIFF_m -z LZW -o tile_ final.pto
   multiblend --wrap --wideblend -o stitched_base.tif tile_*.tif
   ```
   **Важно:** Выходной файл `stitched_base.tif` сохраняет **альфа-канал** (маску реального покрытия кадров дрона). В верхней неснятой зоне зенита альфа-канал равен $0$, а там, где кадры дрона присутствуют — $255$.

## 4. Архитектура Модуля 2: Индексация, подбор неба и умный блендинг с защитой объектов

### Шаг 2.1. Автоматическая индексация базы неба (`scripts/index_skies.py`)
Скрипт сканирует папку `sky_templates/` и создает `sky_catalog.json`.

1. **Автоматическое определение высоты солнца $Y_{\text{sun\_sky}}$ на шаблоне:**
   * Так как солнце по горизонтали всегда находится в центре ($X = 7500$), скрипт вырезает центральный вертикальный столбец шириной $400\text{ пикселей}$: $X \in [7300, 7700], Y \in [0, 3750]$.
   * Переводит столбец в пространство CIE LAB и вычисляет сглаженный вертикальный профиль яркости $L(y)$ и синевы $b(y)$ (гауссово сглаживание с $\sigma = 50\text{ px}$).
   * Сравнивает яркость в центре ($X = 7500$) с яркостью на краях шаблона ($X = 0$, анти-солнце). Если направленная асимметрия мала ($\Delta L < 8.0$) и нет локализованного пика яркости, шаблон помечается как **пасмурный (`is_overcast_template = True`, `sun_y = None`)**.
   * Если выраженный максимум есть, координата $Y_{\text{sun\_sky}}$ вычисляется как центр тяжести (взвешенное среднее) верхних $5\%$ самых ярких пикселей профиля $L(y)$.
   * *Ручное переопределение:* Если в `sky_catalog.json` или в имени файла (например, `sky_01_sunY2450.jpg`) пользователь вручную указал высоту солнца, скрипт приоритетно использует ручное значение.

2. **Формирование паспорта из $N = 20$ вертикальных срезов:**
   В рабочей полосе над горизонтом $Y \in [2850, 3650]$ шаблон делится на $20$ вертикальных столбцов. В каждом столбце сохраняются:
   * $K = 6$ опорных точек вертикального градиента $(L^*, a^*, b^*)$ снизу вверх;
   * 16-биновая гистограмма яркости $L^*$ и канала $b^*$ (для метрики Вассерштейна EMD);
   * Частотная энергия облаков (Difference of Gaussians на радиусах $15\text{ px}$ и $60\text{ px}$).

### Шаг 2.2. Расчет астрономического положения солнца по местному времени и GPS
1. Из EXIF первого снимка извлекаются координаты (`GPSLatitude`, `GPSLongitude`) и строка `DateTime`.
2. Библиотека `timezonefinder` (`TimezoneFinder().timezone_at(lng=lon, lat=lat)`) определяет точный часовой пояс точки съемки (например, `America/Los_Angeles` или `Europe/Moscow`).
3. Местное время `DateTime` переводится в `UTC` через стандартный модуль `zoneinfo` и передается в `astral.sun.azimuth` и `astral.sun.elevation`.
4. Вычисляются точные пиксельные координаты солнца на панораме:
   $$X_{\text{sun\_pano}} = \left( 7500 + \frac{\phi_{\text{sun}}}{360^\circ} \cdot 15000 \right) \bmod 15000, \quad Y_{\text{sun\_pano}} = 3750 \cdot \left( 1 - \frac{\theta_{\text{sun}}}{90^\circ} \right)$$
5. Дополнительно по разбросу экспозиции верхнего ряда кадров ($\Delta EV_{100}$) определяется индикатор пасмурной погоды на панораме (`is_overcast_pano`).

### Шаг 2.3. Двухступенчатый выбор заготовки неба
1. **Ступень 1 (Сравнение 20 вертикальных срезов):**
   * Полоса неба панорамы $Y \in [2850, 3650]$ циклически сдвигается (`np.roll`) так, чтобы $X_{\text{sun\_pano}}$ встал в точку $X = 7500$.
   * **Очистка срезов от высотных объектов (зданий, кранов, ЛЭП):** Внутри каждого из 20 срезов отбрасываются пиксели с высоким градиентом Собеля (провода, фермы кранов, края зданий) и темные пиксели ниже 45-го перцентиля яркости $L^*$, а также пустые пиксели ($\alpha_{\text{stitched}} == 0$).
   * По чистым пикселям неба рассчитывается расстояние до каждого шаблона в `sky_catalog.json` (комбинация вертикального LAB-профиля, EMD-гистограмм, текстуры облаков и разницы высот солнца $\left|Y_{\text{sun\_pano}} - Y_{\text{sun\_sky}}\right|$). Отбираются **Топ-5 кандидатов**.
2. **Ступень 2 (Арбитраж микро-блендингом):**
   * На уменьшенных в $25$ раз копиях ($600 \times 150$) выполняется пробное слияние Топ-5 кандидатов с панорамой. Выбирается шаблон с минимальной стоимостью шва (минимальная необходимая цветокоррекция + минимальный скачок вертикальной производной яркости).

### Шаг 2.4. Защита высотных объектов (ЛЭП, краны, здания) и градиентный блендинг
Поскольку в городском и строительном ландшафте здания, стрелы кранов и опоры/провода ЛЭП часто поднимаются выше горизонта ($Y < 3750$), простой одномерный вертикальный градиент сделает их полупрозрачными. Чтобы избежать этого, строится **комбинированная двумерная альфа-маска** $\alpha_{\text{final}}(x, y)$:

1. **Учет реальной границы кадров дрона ($M_{\text{void}}$):**
   По альфа-каналу `stitched_base.tif` определяется верхняя граница реального изображения в каждом столбце $Y_{\text{top\_edge}}(x)$ (обычно около $Y \approx 2600\text{--}2900$).
   * Выше $Y_{\text{top\_edge}}(x)$ пикселей от дрона нет вообще — там вес нового неба обязан быть $\alpha = 1.0$.
   * Базовый вертикальный S-градиент (`Smoothstep`, $\alpha_{\text{grad}}(x, y) = 3t^2 - 2t^3$) растягивается индивидуально для каждого столбца $x$ от $Y_{\text{start}}(x) = Y_{\text{top\_edge}}(x) + 50\text{ px}$ (где $\alpha = 1.0$) до линии горизонта $Y_{\text{end}} = 3750$ (где $\alpha = 0.0$).

2. **Маска защиты высотных объектов ($M_{\text{sky}}(x, y)$) в зоне $[Y_{\text{top\_edge}}, 3750]$:**
   Чтобы новое небо ложилось только на старое небо, но **не закрашивало** здания, краны и провода ЛЭП:
   * В полосе перехода строится цветовая модель «родного неба» панорамы (по медиане и ковариации $(L^*, a^*, b^*)$ чистых участков неба в каждом секторе).
   * Для каждого пикселя вычисляется расстояние Махаланобиса (или взвешенное евклидово расстояние в LAB) до цвета родного неба в данном азимутальном секторе, дополненное детектором высокочастотных линий (высокий отклик Лапласиана/Собеля на темных проводах ЛЭП и тросах кранов).
   * Формируется грубая маска принадлежности к небу $M_{\text{raw}}(x, y) \in [0, 1]$ (где $1$ — небо, $0$ — здание/кран/ЛЭП).
   * Маска уточняется по контурам с помощью быстрого **Guided Filter** (`cv2.ximgproc.guidedFilter(guide=pano_rgb, src=M_raw, radius=15, eps=1e-3)`). Guided Filter идеально повторяет тонкие грани в $1\text{--}2\text{ пикселя}$ (провода ЛЭП, решетчатые стрелы кранов) без ореолов (halo).
   * *Краевое условие на самом верху кадра:* Если очень высокий объект (например, мачта или здание в 10 метрах от дрона) упирается прямо в верхний срез кадра $Y_{\text{top\_edge}}(x)$ и обрезается им, в узкой полосе $40\text{ px}$ ниже $Y_{\text{top\_edge}}(x)$ маска плавно сводится к $1.0$, чтобы у обрезанной верхушки не было жесткого горизонтального среза на фоне неба.

3. **Итоговое смешивание с затухающей цветокоррекцией Рейнхарда:**
   * Шаблон неба циклически сдвигается по солнцу: `np.roll(sky_img, shift=x_sun_pano - 7500, axis=1)`.
   * В пространстве LAB применяется цветокоррекция шаблона под цвет горизонта панорамы (с весом $100\%$ у горизонта и плавным ослаблением к зениту).
   * Итоговый вес нового неба:
     $$\alpha_{\text{final}}(x, y) = \max\left( M_{\text{void}}(x, y), \; \alpha_{\text{grad}}(x, y) \cdot M_{\text{sky}}(x, y) \right)$$
   * Слияние выполняется в срезе `pano[0:3750, :]`, после чего результат сохраняется в JPEG (`quality=96`, `4:4:4`) с записью EXIF и XMP `GPano`.

### Базовый `Dockerfile` для воспроизводимой среды:
```dockerfile
FROM ubuntu:24.04

ENV DEBIAN_FRONTEND=noninteractive

# Установка системных зависимостей: Hugin CLI, Multiblend, libvips, ExifTool и OpenCV-библиотек
RUN apt-get update && apt-get install -y --no-install-recommends \
    python3 python3-pip python3-venv \
    hugin-tools enblend \
    libvips-dev libimage-exiftool-perl \
    libgl1 libglib2.0-0 build-essential git cmake \
    libtiff-dev libjpeg-dev libpng-dev \
    && rm -rf /var/lib/apt/lists/*

# Сборка актуального Multiblend из исходников (для максимальной скорости сшивки)
RUN git clone https://github.com/DavidHorm/multiblend.git /tmp/multiblend \
    && cd /tmp/multiblend && mkdir build && cd build \
    && cmake .. && make -j$(nproc) && cp multiblend /usr/local/bin/ \
    && rm -rf /tmp/multiblend

WORKDIR /app
COPY requirements.txt .
RUN pip3 install --no-cache-dir --break-system-packages -r requirements.txt

COPY . .
ENTRYPOINT ["python3", "scripts/run_pipeline.py"]
```
